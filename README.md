Multi-Task NLP Transformer and LLM-as-a-Judge Evaluation

This repository contains a from-scratch implementation of a GPT-2-style decoder-only Transformer and the research code used for evaluating local Large Language Model (LLM) judges against human ratings.

The accompanying research paper investigates whether self-consistent LLM judge scores necessarily correspond to human judgments. The empirical evaluation uses an instruction-tuned GPT-2 (124M) model to generate responses, nine human annotators as the human reference, and two local open-weight LLM judges: LLaMA-3-8B and Qwen2.5-7B.

1. Project Overview

The project has two related components:

A from-scratch implementation of a GPT-2-style 124M-parameter decoder-only Transformer in PyTorch.
An empirical LLM-as-a-Judge evaluation pipeline used in the accompanying study.

The Transformer implementation includes model construction, pretrained weight loading, tokenization, text generation, and fine-tuning utilities.

The research component provides a controlled evaluation protocol for comparing local LLM judge scores with human ratings.

The research evaluation is the primary component relevant to the accompanying manuscript.

2. Research Study Overview
Research Question

The study examines whether high self-consistency of an LLM judge should be interpreted as evidence of high reliability or human alignment.

The evaluation separates two concepts:

Self-consistency: whether the same judge gives similar scores when evaluating the same response repeatedly.
Human alignment: how closely judge scores agree with aggregate human ratings.

A judge can therefore be highly consistent while still disagreeing with human evaluators.

3. Experimental Design

The study evaluates responses generated by an instruction-tuned GPT-2 model with 124M parameters.

Dataset

The evaluation contains:

100 questions
5 task categories
20 questions per category
3 generated responses per question
300 total responses
9 human annotators
Scores on a 0–100 scale

The five evaluation categories are:

Factual knowledge
Instruction following
Mathematics
Reasoning
Writing

Each response is associated with its question, category, generation configuration, model output, and human annotations.

The aggregate human score is used as the primary human reference.

4. Response Generation

Three decoding configurations were used to obtain multiple responses for each question:

Configuration	Temperature	Top-k
Low	0.3	10
Medium	0.7	50
High	1.2	100

Each question contributes one response under each decoding configuration, resulting in:

100 questions × 3 responses = 300 responses

The purpose of using multiple decoding configurations is to introduce variation in generated responses while keeping the evaluation protocol controlled.

5. Human Evaluation

Each of the 300 responses was independently scored by nine human annotators using a 0–100 scale.

The human evaluation provides an aggregate reference score for each response.

Human–human agreement was also measured to assess the reliability of the human reference. The study reports:

Mean pairwise Pearson correlation: 0.967
Pairwise Pearson correlation range: 0.939–0.990
ICC(2,k) absolute agreement: 0.996

The annotator identities are represented using anonymized labels in the research data.

6. Local LLM Judges

Two local open-weight LLMs were evaluated as automatic judges:

LLaMA-3-8B
Qwen2.5-7B

Both judges use the same explicit scoring rubric.

The models are executed locally through Ollama.

The purpose of using two different judges is to examine whether self-consistency and human alignment behave similarly across different local LLM judges.

7. Evaluation Rubric

The research evaluation uses:

research/judge_prompt_v2.txt

The rubric evaluates responses using the following dimensions:

Correctness
Instruction following
Relevance and completeness
Clarity and coherence
Writing constraints

The scoring rubric defines score ranges from 0 to 100 using explicit anchors:

0–20
21–40
41–60
61–80
81–100

The rubric is kept fixed across the two judge models and repeated evaluations.

The prompt does not instruct judges to reward verbosity or model identity.

8. Repeated Judge Evaluation

Each response is evaluated three times by each LLM judge.

The experiment uses seed bases:

42
43
44

Thus, the total number of automated judge evaluations is:

300 responses × 2 judges × 3 repetitions = 1,800 evaluations

Repeated evaluations are used to measure judge self-consistency.

The research runner supports incremental checkpointing and retries so that long-running local evaluation jobs can be resumed without losing completed results.

The analysis compares the mean judge score for each response against the aggregate human score.

10. Research Analysis Script

The main analysis script is:

research/analyze_tmlr.py

It computes the statistical analyses required for the study, including:

Human–human agreement
ICC(2,k)
Human-vs-judge Pearson correlation
Human-vs-judge Spearman correlation
MAE
Signed bias
Bootstrap confidence intervals
Category-level analysis
Decoding-level analysis
Self-consistency
Response-length analysis
Length-controlled partial correlations
Optional judge-vs-judge analysis

The reported confidence intervals use 5,000 bootstrap resamples with the fixed analysis seed: 20260908

11. Running the Multi-Judge Evaluation

The main evaluation runner is:

research/run_multi_judge.py

The strengthened experiment can be run using:

bash
python research/run_multi_judge.py \
    --input research/data/combined_human.csv \
    --output research/data/multi_judge_results.csv \
    --judge_models llama3 qwen2.5:7b \
    --repeats 3 \
    --seed_base 42 \
    --retries 3

This requires the corresponding Ollama models to be available locally.

The exact model availability and Ollama configuration should be verified in the local environment before running the experiment.

12. Running the Statistical Analysis

After the multi-judge evaluation has completed:

bash
python research/analyze_tmlr.py \
    --input research/data/multi_judge_results.csv \
    --out_dir research/results/tmlr \
    --judge_means llama3_mean qwen2_5_7b_mean \
    --bootstrap 5000 \
    --seed 20260908

The resulting files are written to:

research/results/tmlr/

The output directory contains the statistical results used to construct the tables and figures reported in the manuscript.

13. Response-Length Robustness Analysis

The study additionally investigates whether response length explains human–judge disagreement.

For each response, character length is measured and correlations are computed between response length and:

Human score
LLaMA judge score
Qwen judge score

Partial correlations are then computed between human and judge scores while controlling for response length.

This analysis is implemented in the research analysis pipeline.

14. Main Empirical Findings

The final validated experiment reports the following overall results.

LLaMA-3-8B

Pearson correlation with human scores: 0.275
Spearman correlation: 0.258
MAE: 27.71
Signed bias: +23.04
Mean item-level SD across repeated evaluations: 0.277
Exact consistency: 97.3%

Qwen2.5-7B

Pearson correlation with human scores: 0.340
Spearman correlation: 0.303
MAE: 18.64
Signed bias: +9.54
Mean item-level SD across repeated evaluations: 0.395
Exact consistency: 92.3%

These results illustrate the central observation of the study:

High self-consistency does not necessarily imply high agreement with human judgments.

Qwen2.5-7B shows stronger overall agreement with human ratings and lower MAE than LLaMA-3-8B in this experimental setting, while both judges remain substantially less aligned with humans than their high self-consistency might suggest.

These findings should be interpreted within the scope of the dataset, models, rubric, and evaluation protocol described in the accompanying manuscript.

16. Original GPT-2 Implementation

The src/ directory contains a from-scratch implementation of a GPT-2-style decoder-only Transformer.

src/model.py

Implements the GPT-style Transformer architecture, including:

Multi-head causal self-attention
Learned positional embeddings
Pre-layer-normalized Transformer blocks
GELU feed-forward layers
Weight-tied output projection

src/weight_loader.py

Provides utilities for loading pretrained GPT-2 weights and transferring them into the from-scratch implementation.

src/tokenizer.py

Provides the BPE tokenizer interface used by the model.

src/generate.py

Contains text-generation utilities including:

Greedy decoding
Temperature scaling
Top-k sampling

These components support the response-generation experiments used in the broader project.

17. Pretrained Checkpoint

The full instruction-tuned GPT-2 checkpoint is not included in the supplementary package because of its file size.

The checkpoint can be supplied separately in the local research environment according to the project setup.

The supplementary package therefore contains the code and evaluation artifacts needed to understand and reproduce the research pipeline without distributing the large model checkpoint.

21. Research Scope

The conclusions of the accompanying study are limited to the evaluated:

GPT-2 124M response-generation setting
Five task categories
100-question dataset
300 generated responses
Nine human annotators
Two local LLM judges
Fixed scoring rubric
Three repeated judge evaluations
Statistical analysis protocol

The results should therefore not be interpreted as establishing that all LLM judges behave in the same way across all models, datasets, domains, or evaluation settings.
